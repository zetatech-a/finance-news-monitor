# AGENTS.md — Finance News Monitor

## Mission

Daily Korean financial news (loan-business/대부업권 focus) monitor: Naver News API → rule + ML relevance filter → sector/topic tagging → same-issue clustering → extractive summaries (+ optional display-only Gemini 3-line summaries) → Markdown/HTML reports, metrics JSON, and email. Runs every day on GitHub Actions (`daily.yml`).

Full pipeline, data structures, env vars, and API details: **`docs/ARCHITECTURE.md`**. Read the relevant section before changing a module.

## Commands (run before every PR)

```bash
pip install -r requirements.txt pytest
python -m pytest tests/ -q
python -m src.run_daily --dry_run          # verify window calculation only
```

- Some replay tests read historical commits. In a shallow clone run `git fetch --unshallow` (or a deep `--depth`) first, otherwise 4 replay tests fail for reasons unrelated to your change.
- A guard test fails while `.github/workflows/daily.yml` or `src/ml/` have uncommitted edits. When editing them intentionally, run with `ALLOW_DELIVERY_SCHEDULE_CHANGES=1`.
- Tests must not touch the network (SMTP/HTTP are faked via monkeypatch).

## Non-negotiable invariants

### Pipeline order and classification
- Gemini 3-line summaries are **display-only**: they fill `Article.summary_lines` after visible items and Top 10 are fixed. Never write Gemini output into `Article.description` or move that step earlier.
- The extractive summary *does* overwrite `description` and feeds re-tagging and Top-10 ranking. Keep that order.
- `queries.yml` holds only base keyword lists; tagging is shaped by overrides in `src/pipeline/tagger.py`. When adding sectors/topics/keywords, check whether an override entry is also needed.
- Do not simplify Korean term guards in `text_matcher.py` / `tagger.py` (`은행`, `신협`, `금융위`, `보험`, `대부`, `여전`, `리스` …).
- The negative-score carve-out lives only in `relevance_score.py`; do not add it to `_rule_decide_relevance`.

### Data model
- Declare every pipeline-populated attribute on the `Article` dataclass; never attach fields with `setattr`.
- Read dict-or-Article fields with `field_value()` / `unwrap_article()` from `src/pipeline/fields.py`.

### ML models
- Train and serve with `model_input_text(title, summary)` from `src/ml/relevance_model.py`. Never build model input inline.
- Never copy the candidate model over `models/relevance.joblib`.
- Missing or broken models fall back (`candidate_hybrid` → rules, or `rule_only`); never raise.

### Gemini
- Never call one article per request on the normal path; use micro-batches (default 25). Do not make "send 50, then split on 400" the default.
- Never re-send articles that already succeeded.
- `usable=false` with a valid reason and empty lines is a normal response: do not cache it, retry it, or count it as an error. `usable=true` with `reason != "ok"` or a broken 3-line contract is a structural violation (retry).
- 429/5xx/timeout: retry the same batch; 400: split without retry.
- No `except Exception: pass` around Gemini. Programming errors raise `GeminiProgrammingError`; only `run_daily.apply_gemini_summaries` absorbs them, logging `exc_info=True`.
- `DEFAULT_MODEL` is the single model definition. No automatic model fallback. Use only the `google-genai` SDK.
- Bump `PROMPT_VERSION` / `SCHEMA_VERSION` when the prompt or schema changes — not for a model change alone.
- Gemini cache is its own file (`gemini_summary_cache.json`); never touch `summary_cache.json` for it. Do not cache summaries built from snippets after a failed body fetch.
- Never put URLs in prompts; sanitize angle brackets with `sanitize_article_text()`.
- Do not hardcode free-tier RPM/TPM/RPD numbers.
- Strict Gemini smoke checks belong only in `smoke.yml`. Never add them to `daily.yml`.

### Logging and secrets
- Never log API keys, full article bodies, prompts, full responses, or full URLs (host only via `safe_host()`).
- Never commit secrets. `.env.example` only; real values in GitHub Secrets.

### Delivery
- Email is one atomic SMTP send (envelope BCC). No per-recipient loops.
- Email requires today's report; never fall back to an older report.
- `daily.yml` concurrency stays `cancel-in-progress: false`.
- Never hand-edit files under `reports/`; they are regenerated by CI.

## Definition of done

- `python -m pytest tests/ -q` passes (with full history, see above).
- New behavior has a test; test assertions, not phase-named file names, are the spec.
- No unrelated refactors in the same PR. PR description follows `.github/pull_request_template.md`.

## Language

- Code, identifiers, commit messages: English. Comments and docs may be Korean (existing style).
